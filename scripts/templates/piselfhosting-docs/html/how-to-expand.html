Expanding Your PiSelfhosting Environment

The PiSelfhosting project provides a solid foundation for common self-hosted services. However, its design is inherently modular and extensible, allowing you to easily add applications or services that are not natively included in the core project. This guide outlines the principles and best practices for integrating new services into your existing PiSelfhosting ecosystem.

You can expand your setup to include almost any Docker-compatible application, leveraging the shared network, Nginx Proxy Manager for external access, and MQTT for inter-service communication.

---

Adding New Docker Compose Services

The most straightforward way to add a new service is by creating a new Docker Compose file for it and integrating it into your existing Docker network.

Steps:

  1. Create a New Directory: Create a dedicated directory for your new service under /home/PiSelfhosting/docker/. 
    mkdir -p /home/PiSelfhosting/docker/my-new-service
  2. Create a docker-compose.yml: Inside this new directory, create a docker-compose.yml file for your service. Ensure it's compatible with Docker Compose V3.8. 
    # /home/PiSelfhosting/docker/my-new-service/docker-compose.yml
version: '3.8'

services:
  my-app:
    image: my-awesome-app/image:latest # Replace with your desired Docker image
    container_name: piselfhosting-my-app
    restart: unless-stopped
    ports:
      - "8090:80" # Map host port 8090 to container port 80
    volumes:
      - my_app_data:/data # Persistent volume for your app's data
      - /etc/localtime:/etc/localtime:ro # Optional: for correct time
    environment:
      - PUID=1000 # Your user ID on the host (check with 'id -u')
      - PGID=1000 # Your group ID on the host (check with 'id -g')
      - TZ=Europe/Amsterdam
      # Add other environment variables required by your application
    networks:
      - piselfhosting_net # Crucial: Connect to the existing PiSelfhosting network

volumes:
  my_app_data:
    name: piselfhosting-my-app-data # Define the named volume

networks:
  piselfhosting_net:
    external: true # Crucial: Reference the external PiSelfhosting network
  3. Start the Service: Navigate to your new service's directory and start it: 
    cd /home/PiSelfhosting/docker/my-new-service
docker compose up -d

    Alternatively, you could add this new service's compose file to the main unified docker-compose.yml (located at /home/PiSelfhosting/docker-compose.yml) by manually merging its services, volumes, and networks definitions. However, starting it individually as above is often simpler for standalone additions.

Integration with Nginx Proxy Manager (NPM)

For external access via a custom domain name and SSL/TLS encryption, you'll want to integrate your new service with Nginx Proxy Manager.

Steps:

  1. Access NPM UI: Navigate to http://[your-pi-ip]:81 in your web browser.
  2. Add a New Proxy Host:
    • Go to "Hosts" -> "Proxy Hosts" and click "Add Proxy Host".
    • Domain Names: Enter the custom domain you want to use (e.g., my-app.yourdomain.com). Ensure this domain's A record points to your public IP address.
    • Scheme: Usually http (as Docker containers often use HTTP internally, and NPM handles SSL).
    • Forward Hostname / IP: Enter the Docker service name of your application (e.g., my-app as defined in its docker-compose.yml). Since NPM is on the same Docker network (piselfhosting_net), it can resolve other service names directly.
    • Forward Port: Enter the internal container port of your application (e.g., 80 from the example above).
    • SSL: In the "SSL" tab, request a new Let's Encrypt certificate for your new domain.

Once configured in NPM, your new service will be accessible via your custom domain with HTTPS.

Integration with MQTT (Mosquitto)

If your new service needs to send or receive real-time data, it can integrate with the existing Mosquitto MQTT broker. This is particularly powerful for home automation, IoT, and event-driven applications.

Steps:

  1. Ensure Mosquitto is Running: Verify the Mosquitto service is active in your PiSelfhosting deployment.
  2. Connect New Service to MQTT: Configure your new application to connect to the Mosquitto broker.
    • MQTT Host: Within your new service's Docker Compose environment variables or configuration, set the MQTT host to mosquitto (the Docker service name for Mosquitto).
    • MQTT Port: The default MQTT port is 1883.
    • Credentials: If you've secured Mosquitto (disabled anonymous access), provide the MQTT_USER and MQTT_PASS from your .env file.

Example MQTT environment variables in a docker-compose.yml: 

environment:
  - MQTT_BROKER_HOST=mosquitto
  - MQTT_BROKER_PORT=1883
  - MQTT_USERNAME=${MQTT_USER}
  - MQTT_PASSWORD=${MQTT_PASS}

This allows your new application to publish and subscribe to MQTT topics, enabling seamless communication with other MQTT-aware services in your PiSelfhosting ecosystem.

Leveraging Frigate for Home Automation and Dashy Stills

Frigate, as your AI-powered NVR, can act as a powerful event source for other applications. Its MQTT integration is key to creating advanced automations and dynamic dashboards.

Frigate & Home Assistant Automations:

  • If you've deployed Home Assistant, its native Frigate integration (via HACS or MQTT auto-discovery) allows you to use Frigate's object detection events (e.g., "person detected," "car parked") as triggers for complex home automations.
  • For example, turn on specific lights when a person is detected in your driveway after dark, or send a rich notification with a snapshot when a package is identified.

Displaying Camera Stills on Dashy:

While not yet fully automated in the core PiSelfhosting scripts, the architecture supports displaying live camera stills or updated snapshots from Frigate directly on your Dashy dashboard.

  • Frigate exposes a direct endpoint for snapshots (e.g., http://[frigate-ip]:5000/api/[camera_name]/latest.jpg).
  • You would typically configure a custom Dashy tile with an image URL pointing to this endpoint. This could be done manually in Dashy's conf.yml or automated in a future enhancement of the dashy_tile_config_tool.py script.
  • This would provide a real-time visual overview of your cameras directly on your main dashboard.
