Nginx Proxy Manager: Reverse Proxy & SSL Management

Nginx Proxy Manager (NPM) is a powerful tool that simplifies the complex process of running a reverse proxy with SSL termination. It provides a clean, web-based interface to manage Nginx proxy hosts, redirects, and most importantly, obtain and renew free SSL certificates from Let's Encrypt. This allows you to expose your self-hosted services securely to the internet using your own domain names.

Within the PiSelfhosting project, NPM is a critical component for securely accessing your services from outside your local network via human-readable domain names (e.g., nextcloud.yourdomain.com instead of your-pi-ip:8081).

---

Detailed Functionality

Key Features:

  • Web-based UI: Easy creation and management of proxy hosts without needing to manually edit Nginx configuration files.
  • Let's Encrypt Integration: Seamlessly obtain and automatically renew free SSL/TLS certificates for your domains, providing secure HTTPS access.
  • Reverse Proxy: Forward requests from your custom domain names (e.g., nextcloud.yourdomain.com) to the correct internal Docker container and port (e.g., Nextcloud's container on port 80).
  • Custom Locations & Redirects: Configure specific proxy rules or redirect domains to other URLs.
  • Access Control: Implement basic authentication for your proxy hosts if needed.
  • DNS Challenge Support: Supports both HTTP-01 and DNS-01 challenges for Let's Encrypt.

PiSelfhosting Integration:

The PiSelfhosting project automates the deployment of Nginx Proxy Manager and prepares it for your self-hosted services:

  • Docker Compose Template: The docker-compose.yml.template file in /home/PiSelfhosting/scripts/templates/nginxproxymanager/ defines the NPM service. Key aspects include:
    • Image: jc21/nginx-proxy-manager:latest (the official NPM Docker image).
    • Ports:
      • 80:80 (HTTP) and 443:443 (HTTPS): These are the primary ports for NPM to listen on for incoming web traffic. These ports must be forwarded from your router to your Raspberry Pi.
      • 81:81: The dedicated port for NPM's web-based administration interface.
    • Volumes: Dedicated named volumes (npm_data and npm_letsencrypt) ensure persistent storage of NPM's internal database, configurations, and crucially, your Let's Encrypt certificates.
    • Environment variables: NPM connects to your MariaDB service using environment variables like DB_MYSQL_HOST (mariadb), DB_MYSQL_USER, and DB_MYSQL_PASSWORD (sourced from your .env file).
    • Dependency: depends_on: - mariadb ensures the database is ready before NPM attempts to start.

Initial Setup & Configuration:

After deploying NPM, you'll perform a one-time setup and then configure your proxy hosts via its web UI:

  1. Access the UI: Navigate to http://[your-pi-ip]:81 in your web browser.
  2. First-time Login:
    • Default Email: admin@example.com
    • Default Password: changeme
    You will be prompted to change these default credentials immediately.
  3. Add Proxy Hosts:
    • Go to "Hosts" -> "Proxy Hosts".
    • Click "Add Proxy Host".
    • Domain Names: Enter your custom domain (e.g., nextcloud.yourdomain.com).
    • Scheme: Usually http (as Docker containers often use HTTP internally, and NPM handles SSL).
    • Forward Hostname / IP: Enter the Docker service name of your application (e.g., nextcloud).
    • Forward Port: Enter the internal container port of your application (e.g., 80 for Nextcloud).
    • SSL: In the "SSL" tab, select "Request a new SSL Certificate" using Let's Encrypt. Choose an email and agree to the terms. Ensure ports 80/443 are properly forwarded from your router to your Pi for this to work.

Repeat the "Add Proxy Host" steps for each of your services (Nextcloud, Dashy, Frigate's web UI, etc.) that you want to access via a custom domain with SSL.

Troubleshooting

NPM issues, especially with SSL, often relate to network or DNS configuration:

  • Check NPM logs: Use docker logs piselfhosting-nginxproxymanager for errors.
  • Port Forwarding (CRITICAL): Ensure that ports 80 and 443 from your router are correctly forwarded to the IP address of your Raspberry Pi. Without this, Let's Encrypt challenges will fail, and external access will not work.
  • DNS A Record: Verify that your custom domain's A record (e.g., nextcloud.yourdomain.com or yourdomain.com) points to your public IP address.
  • Internal Connectivity: Make sure NPM can reach your backend services over the piselfhosting_net Docker network (e.g., check that ping nextcloud works from within the NPM container if you attach to it).
  • MariaDB Connection: Check that NPM can connect to your MariaDB database. Review DB_USER and DB_PASS in your .env file.
  • SSL Certificate Manager Tool: The SSL Certificate Manager tool provides specific instructions for obtaining certificates and diagnosing issues.
  • Official Documentation: The official Nginx Proxy Manager documentation is highly recommended.
