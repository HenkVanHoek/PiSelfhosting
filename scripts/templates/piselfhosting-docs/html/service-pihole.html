Pi-hole: Network-wide Ad Blocking

Pi-hole is a DNS sinkhole that protects all your devices from unwanted content, such as ads, trackers, and malicious websites. By acting as your network's DNS server, it blocks requests to blacklisted domains before they even reach your devices, offering a clean Browse experience and enhanced privacy across your entire network, including IoT devices that might not support ad blockers directly.

As part of the PiSelfhosting project, Pi-hole gives you central control over content filtering for all devices connected to your home network.

---

Detailed Functionality

Key Features:

  • Network-wide Protection: Blocks ads and trackers for all devices on your network, regardless of their operating system or browser.
  • DNS-based Filtering: Operates at the DNS level, blocking requests before they reach your devices.
  • Customizable Blacklists & Whitelists: Add your own domains to block or allow, and use community-maintained blocklists.
  • Centralized Management: A user-friendly web interface provides detailed statistics, query logs, and easy configuration.
  • DHCP Server: Can optionally act as your network's DHCP server, simplifying network setup.
  • Lightweight: Designed to run efficiently on low-powered devices like the Raspberry Pi.

PiSelfhosting Integration:

The PiSelfhosting project automates the deployment of Pi-hole in a Docker container, making it easy to set up your network-wide ad blocker:

  • Docker Compose Template: The docker-compose.yml.template file in /home/PiSelfhosting/scripts/templates/pihole/ defines the Pi-hole service. Key aspects include:
    • Image: pihole/pihole:latest (the official Pi-hole Docker image).
    • Environment variables:
      • TZ: Sets the timezone for accurate logging.
      • WEBPASSWORD: Configures the password for the Pi-hole web interface, pulled from your .env file.
      • DNSMASQ_LISTENING=all: Ensures Pi-hole listens for DNS queries on all available network interfaces.
      • FTLCONF_PIHOLE_DNS_PORT=53: Explicitly sets the DNS port.
    • Volumes: Dedicated named volumes (pihole_etc and pihole_dnsmasq) ensure persistent storage of Pi-hole's configuration and DNSmasq settings.
    • Ports:
      • 53:53/tcp and 53:53/udp: These are essential mappings for DNS traffic. **Crucially, these ports must be free on your host system** or carefully managed to avoid conflicts if you intend to use Pi-hole as your primary DNS server.
      • 8082:80: Maps the Pi-hole web interface to port 8082 on your host, preventing conflicts with other services that might use port 80.
    • cap_add: - NET_ADMIN: Grants the container the necessary network administration capabilities required for Pi-hole's operation.

Post-Deployment & Network Configuration:

After deploying Pi-hole, you'll need to configure your network to use it as the primary DNS server. There are generally two methods:

  • Router Configuration (Recommended):

    Access your router's administration interface and change the DNS server setting to the IP address of your Raspberry Pi. This will apply Pi-hole's ad-blocking capabilities to all devices connected to your network.

  • Individual Device Configuration:

    Manually set the DNS server on each device to the IP address of your Raspberry Pi. This is less convenient but provides granular control.

  • DHCP Server (Advanced):

    You can disable the DHCP server on your router and enable Pi-hole's built-in DHCP server. This gives Pi-hole full control over network IP address assignment and DNS distribution.

Troubleshooting

If you encounter issues with Pi-hole:

  • Check Pi-hole logs: Use docker logs piselfhosting-pihole for container-specific errors. You can also view logs from the Pi-hole web interface.
  • Verify DNS Configuration: Ensure your router or devices are correctly pointing to your Raspberry Pi's IP address as the DNS server.
  • Port Conflicts: Double-check that no other service on your Raspberry Pi is using port 53 (DNS).
  • Web Interface Access: If you can't access the web interface on port 8082, check firewall rules or other services potentially using that port.
  • FTL Service: In the Pi-hole web interface, check the status of the "DNS service" or "FTL" (Fregment of Time Logic) service. If it's down, try restarting the container.
  • Official Documentation: The official Pi-hole documentation and their community forums are excellent resources for troubleshooting.
