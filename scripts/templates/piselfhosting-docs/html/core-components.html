Understanding the Core of PiSelfhosting

The PiSelfhosting project is built on a set of core scripts and configuration files that automate the deployment and management of your self-hosted services. These components work together to provide a streamlined, command-line driven experience for setting up your Raspberry Pi as a versatile home server.

By understanding these core elements, you'll gain insight into how your PiSelfhosting environment is structured and how to effectively manage it.

---

setup.sh: The Initial Setup Wizard

The setup.sh script is your starting point for building the PiSelfhosting environment. It's designed as an interactive wizard that guides you through the initial configuration steps.

Detailed Functionality:

  • Prerequisite Installation: It first checks for and installs necessary tools like whiptail, which is used to create the interactive text-based user interface.
  • Environment Variable Collection: The script prompts you for essential network and service-specific details, such as your main domain name, database credentials, Nextcloud admin details, Pi-hole password, Frigate RTSP credentials, and MQTT user/passwords.
  • .env File Generation: All collected environment variables are securely stored in the .env file located in your base project directory (/home/PiSelfhosting/.env). This file is crucial as Docker Compose services will automatically load these variables.
  • Docker & Docker Compose Installation (on Host): This script plays a vital role in setting up the foundational Docker environment on your **Raspberry Pi's operating system (host)**. It ensures that the Docker engine (Docker CE) and the Docker Compose V2 plugin are installed and configured. This is a one-time setup on the host itself, independent of the individual Docker containers that will run your services.
  • Component Selection: Using a whiptail checklist, the script allows you to select which PiSelfhosting services you want to deploy from the list defined in components_list.txt. Your choices are saved to selected_components.txt.

To run the setup script: bash /home/PiSelfhosting/scripts/setup.sh

---

deploy.sh: Orchestrating Your Services

After setup.sh has configured your environment and selected components, the deploy.sh script takes over to bring your self-hosted services to life using Docker.

Detailed Functionality:

  • Environment Loading: It loads all previously configured environment variables from your .env file, making them available for container configuration.
  • Pre-Deployment Cleanup: The script performs a thorough cleanup, stopping and removing any existing PiSelfhosting Docker containers, volumes, and networks. This ensures a clean and consistent deployment every time.
  • Unified Docker Compose File Generation: This is a key innovation. Instead of managing individual Docker Compose files for each service, deploy.sh dynamically generates a **single, unified docker-compose.yml file** in your base directory (/home/PiSelfhosting/docker-compose.yml). This file includes definitions for *all selected* services.
  • Configuration from Templates: It processes Docker Compose templates and service-specific configuration templates (e.g., for Frigate or Mosquitto) by filling in placeholders with your environment variables.
  • Component-Specific Actions: The script handles any special requirements for individual services, such as creating specific directories or setting permissions.
  • Helper Script Generation: deploy.sh generates several essential helper scripts (start-all.sh, stop-all.sh, restart-all.sh, remove-component.sh, get_docker_compose_cmd.sh) to simplify future management of your services.

To deploy your services: bash /home/PiSelfhosting/scripts/deploy.sh

---

components_list.txt: Defining Your Services

The components_list.txt file acts as a manifest for all available PiSelfhosting services. It's read by the setup.sh script to present component choices to the user.

Detailed Functionality:

  • Component Order: The COMPONENTS_ORDER line at the top specifies the exact sequence in which services appear in the interactive selection menu.
  • Service Definitions: Each service is defined in its own bracketed section (e.g., [frigate]).
    • description: A human-readable title for the service displayed in the setup wizard.
    • default_selected: Specifies whether the service is 'ON' or 'OFF' by default in the selection menu.
    • Additional attributes (e.g., dashy_tile_section, dashy_tile_icon, dashy_tile_url_suffix, dashy_tile_status_check, config_paths) are used by other scripts (like dashy_tile_config_tool.py and deploy.sh) to further configure the service or its integration with Dashy.

Example entry from components_list.txt: 

[frigate]
description=Frigate (AI-powered NVR)
default_selected=OFF
dashy_tile_section=Smart Home
dashy_tile_icon=fa-solid fa-video
dashy_tile_url_suffix=:5000
dashy_tile_status_check=True

config_tool_base_dockerfile: The Toolkit's Foundation

This Dockerfile is central to all Python-based configuration tools within PiSelfhosting (like those for Dashy, Frigate, Mailserver, and SSL). It defines a lightweight, self-contained environment for these tools to run reliably.

Detailed Functionality:

  • Base Image: Uses a lean Python 3.9 image (python:3.9-slim-buster) to provide the necessary Python runtime.
  • System Dependencies: Installs crucial operating system packages such as ffmpeg (which includes ffprobe for RTSP stream testing in the Frigate tool), libxml2-dev, libxslt1-dev (for lxml), and build-essential for compilation.
  • Python Libraries: Installs essential Python libraries via pip, including pyyaml (for configuration file parsing), onvif-zeep (for ONVIF camera discovery), and lxml.
  • Isolated Environment: By encapsulating the tools and their dependencies, this Dockerfile ensures that the configuration scripts run consistently regardless of your host system's specific setup, preventing dependency conflicts.

This Docker image is built by the wrapper scripts (e.g., run-frigate-camera-config-tool.sh) before executing their respective Python tools.

Helper Scripts: Daily Management Tools

The deploy.sh script automatically generates several helper scripts to simplify the daily management of your PiSelfhosting services. These are located in the /home/PiSelfhosting/scripts/ directory.

Detailed Functionality:

  • start-all.sh:
    • Starts all selected PiSelfhosting services.
    • Ensures the piselfhosting_net Docker network exists.
    • Performs a clean shutdown and removal of old containers before starting new ones, ensuring fresh deployments.
    • Automatically pulls the latest Docker images for your selected services (if --build is used in deploy.sh, which it is).
    • Usage: bash /home/PiSelfhosting/scripts/start-all.sh
  • stop-all.sh:
    • Gracefully stops all running PiSelfhosting Docker containers.
    • Usage: bash /home/PiSelfhosting/scripts/stop-all.sh
  • restart-all.sh:
    • A convenience script that calls stop-all.sh followed by start-all.sh.
    • Useful for applying configuration changes or updating services.
    • Can restart specific services: bash /home/PiSelfhosting/scripts/restart-all.sh frigate
    • Usage: bash /home/PiSelfhosting/scripts/restart-all.sh
  • remove-component.sh:
    • An interactive script that allows you to selectively remove specific PiSelfhosting services from your deployment.
    • It will stop and remove the container, its associated volumes, and update the selected_components.txt file.
    • Usage: bash /home/PiSelfhosting/scripts/remove-component.sh
  • get_docker_compose_cmd.sh:
    • A small internal helper script used by other management scripts.
    • It determines the correct Docker Compose command to use on your system (docker compose for V2 plugin or docker-compose for V1 standalone).
    • You won't typically run this directly.
